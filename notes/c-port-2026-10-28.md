# The engine in C

**Status: started 2026-10-28 (Roland, with Claude).** The language
(parser, imports, compiler, natives) has been C since 2026-10-27; this
moves the rest. About 3,400 lines of Nim remain.

## Why now

- The Nim/C seam costs real time: Nim decides whether to rebuild from
  `.nim` files alone, so after a C change a test binary can run the old
  compiler (it reported a fixed bug as broken on 2026-10-28; `make`
  works round it with `fresh-c`).
- The language's design has settled, and the performance work is now
  in what crosses the seam: block processing, hoisting, state migration.

Not for speed of the hot path, which is already C (the patch and the
natives); for one language, one build, and code a reader can follow.

| 2. the engine | `engine.nim`: the audio loop, guards (NaN, runaway, stuck, rollback), the control socket, parts, fades, sweep | `tests/engine_live.nim`, unchanged, against the new binary |

| 4. the tests | the remaining Nim tests become aither cases (`tests/lang`) or small C and shell tests | — |

## Progress

- **Stage 1, the voice: done 2026-10-28.** `voice.c` / `voice.h` (about
  660 + 130 lines) replace `voice.nim`'s logic and `tcc.nim`;
  `voice.nim` is a 210-line binding. The corpus is bit-identical (156
  files), `make exact` (TCC against cc -O2 on every patch) and the full
  suite pass, the live engine test included. Found on the way: this
  libtcc's `tcc_relocate` takes one argument (the Nim binding passed two,
  silently), and a preview's state buffer must come from C's allocator
  now that C frees it (`allocState`).
- **Stage 2, the engine: done 2026-10-28.** `engine.c` / `engine.h`
  (about 1,620 + 80 lines) replace `engine.nim`'s logic: the pump, the
  voice table and its lock, the guards, the doctor, the -O2 queue, send
  / try / profile / sweep, the gestures, the snapshots, the socket and
  the command language. `engine.nim` is a 240-line binding: `runEngine`,
  the gestures the tests call, and the hooks engine.c declares extern

## Stage 1: the voice

`voice.h` / `voice.c` own a `Voice`: its compiled code (a TCC state,
kept alive while its tick can run, old ones kept for the audio thread),
its state buffer (the generated struct, then its pool), its layout
(var names, regions), its parts (names, gains, fades, meters, parked
flags) and the previous version for rollback. Prepare (compile and
allocate, slow, outside the audio mutex) and commit (migrate and swap,
microseconds, under it) stay two steps.

While the engine is still Nim, `voice.nim` is a binding: the same
names over the C struct, part arrays as `ptr UncheckedArray`, name
lists copied to `seq[string]` where the engine reads them (never on
the audio thread). MIDI's `n_midi_*` stay Nim-exported until stage 3;
`voice.c` declares them extern.

The header the generated code begins with (`VoiceHeader` in Nim) is
written once, in `voice.h`, and codegen.c's emitted struct must match
it field for field (a comment in both says so).

## Stage 2: what to know before starting

- **The engine's jobs** (`engine.nim`, ~1,300 lines): the pump (read a
  block of input, tick every voice's `tick_block`, mix, write; lockstep,
  gapless, the mix yields to a waiting command), the voice table and its
  mutex, send/stop/clear and fades, mute/solo/park on a voice or
  `voice.part` (held/parkAtZero/parked flags), sweep, the guards
  (NaN -> reset pool and scrub, runaway past ±8 -> mute and retry,
  stuck recursion -> rollback or mute, rollback within RollbackWindow
  after a swap), the background -O2 queue (`compileOptimized` then
  `upgrade` if the generation still matches), the control socket and
  its command language, `try` previews (snapshot, render, dispose),
  `profile`, levels and meters, realtime priority (`realtime.c`).
- **The safety net** is `tests/engine_live.nim`: it runs `./aither` as a
  separate process and drives it over the socket, so it doesn't care
  what the engine is written in. Run it, the corpus and `make exact`
  after every step; the corpus must stay bit-identical.
- **The voice is already C** (`voice.h`): call it directly; `voice.nim`
  goes once nothing Nim needs it.
- **MIDI is still Nim** until stage 3 (`n_midi_*` exported from
  `midi.nim`, declared extern in `voice.c`); so are the CLI, the text
  formatting (`cli_output.nim`) and the analysis. A workable order:
  write `engine.c` with a small C API (start, stop, handle a command
  line, pump a block), call it from `aither.nim`, and keep the text
  formatting in Nim until stage 3 by having C return data the Nim side
  formats (as `engine.nim` already returns snapshot objects to
  `cli_output.nim`).
- **Builds:** `make` runs `fresh-c` so test binaries can't run stale C;
  if a result looks impossible, suspect a stale binary first.
- **Roland's rules that apply:** discuss design before changing it;
  spec every language or CLI change in SPEC.md in the same commit; the
  language comes first, but a refactor like this must not change any
  sound (corpus); commit explicit paths; push only when asked.
- **After the port:** remind Roland about control-rate values
  (`slow(...)`), as he asked.
