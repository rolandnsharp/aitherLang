# Handover: after fields, rates, arrays and radio

For a fresh session. Written 2026-10-30. It replaces
[handover-fields-2026-10-29.md](handover-fields-2026-10-29.md) as the
place to start; that one's aim and constraints still hold and are
repeated here in short.

## The aim

Roland: "my whole point of aitherlang is to be the best language to
express field physics." General purpose, "not just for me", and "simplex
and elegant". He judges by elegance and wants to be convinced before a
language change ("lets keep talking about this till im convinced").

## Constraints

- **No machine in patches.** No control rate, no `slow()`; every state
  every sample; speed only from what the compiler proves unheard.
- **Design first.** A note with real patches written both ways, discussed,
  before building. Every language change goes into SPEC in the same
  commit.
- **The corpus** (`make corpus`) stays bit-identical unless a sound
  change is intended. `tests/corpus` links the compiler and stdlib
  statically: `make tests/corpus` before trusting it. It renders patches
  as committed, so commit a patch before recording its line.
- **Measure, don't describe.** Roland prefers numbers to adjectives,
  and doesn't want to be asked to listen to changes too small to hear:
  measure first, and ask him only for what analysis can't judge.
- **Speed:** a `send` runs on TCC (unoptimised) at once, then swaps in a
  background `cc -O2` build; offline renders of 4 s or more are built
  with `cc -O2` first (`AITHER_OPT=0` turns both off). So time renders of
  4 s or more, or say which compiler ran ([perf-2026-10-30.md](perf-2026-10-30.md)).
  Check `/sys/devices/system/cpu/online` before timing; on battery only
  the A53s run, at 1 GHz.
- Commit explicit paths (other sessions work in the same tree); push only
  when asked.

## What was decided, 2026-10-29 and 30

| | decision | note |
|---|---|---|
| fields | **M** (a field is its modes: spin, phase, `kick`, `at`) is aither's field view. **X** (coordinates like `t`) isn't needed: places are state arrays, and read well; X waits for a patch whose places read badly | [fields-2026-10-29.md](fields-2026-10-29.md), [pluck-2026-10-30.md](pluck-2026-10-30.md) |
| spatial audio | in 2-D it needs no construct: a pair array of circular modes, encode and turn are turns, hearing is a sum of turns, a round head and a room. Front and back stay ambiguous without a head tracker. `ears` goes in the stdlib when a second patch wants it | [spatial-2026-10-29.md](spatial-2026-10-29.md), `patches/around.aither` |
| the pair's double meaning | not a design question: a pair is complex only to the operations that turn it; encode with a def that builds the pair (as `pan` does) and a stereo source is refused | spatial note, item 2 |
| stepping | no construct. Measured at three rates, step error hurt one patch (`chaos`) and stdlib defs nobody used; they were fixed locally (`resonator`, midpoint). The design stays on file | [stepping-2026-10-29.md](stepping-2026-10-29.md), [rates-2026-10-30.md](rates-2026-10-30.md) |
| rates | `noise` has a level per Hz; `reverb`'s room is in seconds; `impulse` stays an event and a strike is `impulse(f) / dt` times its size; `hilbert` is a fraction of the rate on purpose. The corpus re-recorded | rates note |
| arrays | `array(n, i => rule)`, for local arrays and as a state array's starting shape. A def doesn't return an array: a def of the index, tabulated, says it. A def still ends in an expression (it is what closes a body) | [arrays-2026-10-30.md](arrays-2026-10-30.md) |
| radio | one engine at the radio's rate, everything playable in the patch, the rate changed at the end of the pipe by `tools/rate` | [radio-2026-10-30.md](radio-2026-10-30.md) |

## Open

- **Radio hardware.** No SDR is attached. An RTL-SDR (USB, or on the
  uConsole's AIO board) gives 8-bit unsigned IQ; a converter to float
  pairs is a tool (or part of `tools/rate`). The receiver in the radio
  note then tunes a real station at 240–300 kHz.
- **`lib/voice`'s tract is in samples**, so `didge_scope` is 18 cents off
  at every rate. Sections in metres with fractional delays would fix it;
  a rewrite, not a patch.
- **X's candidates:** `ridge` and `phased_array` (2-D: row arithmetic and
  edge guards). If either reads badly, that is X's evidence.
- **The places string's grid:** 64 places make its tenth partial 11 to
  18 cents flat and its pitch top out at 350 Hz. A finger or fret is where
  places earn their keep; an instrument mixing both (modes for the body,
  places at the contact) is untried.
- **`ears` to the stdlib** when a second patch hears through a head.
- **Moves files as a tape (Roland's idea, 2026-10-30).** `--play`'s
  script of timed moves is a piano roll as text, and a tape in
  aitherOS's sense (what came in, in order, with its time, replayed
  through the patch). Composed sequencing stays in patches as signals
  (`wave`, tables, `tape` loops); performed sequencing could be this:
  record live MIDI into the same format, edit it as text, play it back
  on a live engine, looped or beside the hands. Not built; offline
  `--play` is.

## A reminder owed

**Waits, by Roland's request to be reminded once the round below is done:**
blocks, SIMD across samples and multicore. They depend on the last big
design question, the spectral gap: whether a patch can process a block at
a time (FFT, convolution) inside a language that's one sample at a time.
That decision shapes how the compiler schedules work; built first, the
deep machinery may have to be redone.
