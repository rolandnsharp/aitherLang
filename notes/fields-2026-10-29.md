# Fields of phasors: which way is aither's

**Status (2026-10-29, later): reopened, for choosing.** A (pair elements
in state arrays) is built and stays underneath whatever is chosen. The
question now is how a field is *written*, measured against aither's aim:
to be the best language for field physics. Two candidates, each written
out below on the same three demos:

- **B, a field and its local law:** `field(shape, init, law)`, the law
  saying how one place's next value follows from it and its neighbours.
  Pairs stay `[a, b]`.
- **V, the field as a value:** a field is a value like a number;
  arithmetic is at every place at once; neighbours are whole shifted
  fields, so ∇² is a def on fields. It needs pairs written `{a, b}`,
  because `[ … ]` has to mean only "a field".

Nothing is built for either yet. The corpus decides nothing here; both
must render the converted demos bit-identical to today.

The test, from MANIFESTO.md: signals as field values, state as field
configuration, **evolution as a local update rule**, observation as
projection, coupling as shared field access. And PHILOSOPHY.md's: every
primitive earns its place against what the existing ones already say.

## The ladder: most fields need no new feature

What physics already reads well, because the kind of field decides it:

| the field | what writes it in aither today | needs state per place? |
|---|---|---|
| a linear medium driven at its modes (a plate, a drum, a room's resonances) | a sum of its modes: `sum(N, n => dho(drive * shape(n, x), f(n), d))` (demos/chladni) | no |
| a linear medium carrying waves (a string, a tube, a room's echoes) | travelling waves as delays (d'Alembert: f(x - ct) + g(x + ct)), a waveguide | no, delays are the field |
| oscillators all coupled to all (Kuramoto's own model, a bridge, a soundboard) | one shared cell, the mean field (sympathy.aither's `$board`) | no: one cell |
| polyphase, rotating fields | turns of one phasor (three_phase.aither) | no |
| **a medium stepped by a local rule** (a membrane by leapfrog, Maxwell by FDTD, a ring of oscillators, a lattice, reaction-diffusion, any per-place iteration) | a stored field: one value per place | **yes** |

Only the last row is in question. B and V are two ways to write it.

## The three demos

Today's forms are the files: `demos/ridge.aither` (a 64×36 membrane by
leapfrog, terrain, a soaking border, a mast), `patches/phasor_ring.aither`
(twelve phasors in a ring, nonlinear), `patches/mandelbrot.aither` (state
at every place, no neighbours, two fields where one feeds the other).
Both forms are written from those, line for line where the physics is the
same; the comments are cut.

### ridge, today (A)

```
let k = pixel_index(w, h)
let x = k mod w
let y = int(k / w)
...
$u = array(w * h, every = w * h)
$v = array(w * h, every = w * h)
let c  = $u[k]
let p  = $v[k]
let lt = if x > 0 then $u[k - 1] else 0
let rt = if x < w - 1 then $u[k + 1] else 0
let up = $u[k - w]
let dn = $u[k + w]
let lap = lt + rt + up + dn - 4 * c
let edge = min(min(x, w - 1 - x), y)
let soak = if edge < 4 then 0.8 + 0.05 * edge else 1
let drive = if k == mast then sin($phase) else 0
let next = if earth then 0 else (2 * c - p + 0.25 * lap) * soak + 0.5 * drive
$u[k] = next
$v[k] = c
let z = [next, (next - c) / omega]
```

The sample computes one place; the program is written from inside that
place. The left and right edges are guarded by hand, because a flat index
wraps across rows.

### ridge in B

```
def lap(at, u): at(-1, 0) + at(1, 0) + at(0, -1) + at(0, 1) - 4 * u
def ground(x): h - 3 - max(0, 14 * (1 - abs(x - 36) / 11.5))
def soak(x, y):
  let edge = min(min(x, w - 1 - x), y)
  if edge < 4 then 0.8 + 0.05 * edge else 1

$u = field([w, h], 0, every = w * h, (u, was, at, place) =>
  let [x, y] = place
  let drive = if x == 5 and y == h - 9 then sin($phase) else 0
  if y >= ground(x) then 0 else (2 * u - was + 0.25 * lap(at, u)) * soak(x, y) + 0.5 * drive)

let next = $u[k]
let z = [next, (next - $u.was[k]) / omega]      # needs a way to read the step before
```

- Good: the leapfrog line is the physics; `at(dx, dy)` is 2-D, so the
  edge guards are gone (past the edge reads 0, the declared edge).
- Awkward: `was` is inside the law, but the picture needs it too
  (the phasor is the field and its rate), so B needs a second way in,
  `$u.was[k]` or such. Everything place-dependent (terrain, soak, the
  mast) becomes a def of `place`, threaded through the law's arguments.
  The law takes four arguments, most laws use two.

### ridge in V

```
let x = across(w, h)                 # a field: every place's column
let y = down(w, h)                   # ... and its row
def lap(u): shift(u, -1, 0) + shift(u, 1, 0) + shift(u, 0, -1) + shift(u, 0, 1) - 4 * u

let earth = y >= h - 3 - max(0, 14 * (1 - abs(x - 36) / 11.5))
let edge = min(min(x, w - 1 - x), y)
let soak = if edge < 4 then 0.8 + 0.05 * edge else 1
let drive = if x == 5 and y == h - 9 then sin($phase) else 0

$u = field([w, h], 0, every = w * h)    # the field now
$v = field([w, h], 0, every = w * h)    # a frame ago
let next = if earth then 0 else (2 * $u - $v + 0.25 * lap($u)) * soak + 0.5 * drive
$v = $u
$u = next

let z = {next[k], (next[k] - $v[k]) / omega}   # the sample: the field seen at this place
```

- Good: it reads like the textbook: u_next = 2u - u_prev + c²∇²u. `lap`
  is ∇², a reusable value. The terrain and the border are fields, written
  as plainly as the numbers were. The two time levels are explicit
  (`$v = $u`), so observation reads either. The sample is a projection,
  `next[k]`: the manifesto's "observation as projection", literally.
- Awkward: `x` is now a field, not this sample's column; a patch that
  wants both says `across(w, h)` and `k mod w`. `if` on a field picks at
  every place. `shift` past the edge reads 0; a soaked or wrapped edge
  is `shift(…, edge = …)`.

### phasor_ring, today (A)

```
$z = array(n, [1, 0])
each(n, i => $z[i] = law($z[i], $z[(i + n - 1) mod n], $z[(i + 1) mod n], step(i, spread), couple))
```

### phasor_ring in B

```
$z = field(n, [1, 0], edge = ring, (z, was, at, i) =>
  let moved = turn(z, step(i, spread)) + (at(-1) + at(1) - z * 2) * couple
  moved / amplitude(moved))
```

### phasor_ring in V

```
let steps = field(n, i => step(i, spread))      # each place's own turn
$z = field(n, {1, 0})
let moved = turn($z, steps) + (roll($z, -1) + roll($z, 1) - $z * 2) * couple
$z = moved / amplitude(moved)
```

Both lose the index arithmetic. V reads as the equation of motion of the
whole ring; B reads as the equation at one oscillator. `roll` wraps
(NumPy's name); `shift` doesn't.

### mandelbrot, today (A)

```
$z = array(w * h, [0, 0])
$m = array(w * h, [0, 0])
let z = $z[k]
let next = if amplitude(z) > 2 then z else turn(z, z) + c
$z[k] = next
let seen = $m[k] + (next - $m[k]) * 0.05
$m[k] = seen
```

### mandelbrot in B

```
$z = field([w, h], [0, 0], every = w * h, (z, was, at, place) =>
  if amplitude(z) > 2 then z else turn(z, z) + point(place))
$m = field([w, h], [0, 0], every = w * h, (m, was, at, place) =>
  m + ($z[place] - m) * 0.05)
```

- Awkward, and it changes the picture: each law reads every field as it
  was, so `$m` follows `$z` a frame late. Two fields where one feeds the
  other inside a step is the shape of Maxwell's equations by FDTD (Yee:
  E from H, then H from the new E), the scheme field physics is computed
  with. B would need an order between laws, which is the thing B was
  meant to avoid.

### mandelbrot in V

```
let c = place_point(w, h) * 1.5 - {0.5, 0}     # every place's point, a field
$z = field([w, h], {0, 0}, every = w * h)
$m = field([w, h], {0, 0}, every = w * h)
let next = if amplitude($z) > 2 then $z else turn($z, $z) + c
let seen = $m + (next - $m) * 0.05
$z = next
$m = seen
seen[k] / (1 + amplitude(seen[k]))
```

The order is the `let`s, as everywhere else in aither. Yee's scheme is
the same shape: `let e = $e + curl($h) * k`, `$h = $h - curl(e) * k`,
`$e = e`.

## What each costs

**B**
- One construct, `field(shape, init, law)`, with `at`, `was`, `place`,
  edges and `every`. Pairs are untouched, nothing migrates.
- It says what `each` with held-back stores already says, more
  specifically (the status this note first had rejected B for that).
- Fails on fields that feed each other inside a step (mandelbrot's two,
  Maxwell's E and H) without an order between laws.

**V**
- Pairs become `{a, b}`: about 245 two-element literals and 57
  `let [a, b] =` destructurings across 95 `.aither` files, plus about 90
  in SPEC, COMPOSING, PHASORS and the stdlib. Mechanical, one commit of
  its own, and the corpus proves it changed no sound. `[a, b]` stops
  meaning a table of two in one place and a pair in another (SPEC,
  "Arrays"): brackets are tables and fields, braces are pairs.
- A field type in the compiler: a shape, and every pure operation and
  pure builtin applied at every place. `field(n, i => …)` tabulates,
  `across`/`down`/`place_point` give coordinates, `shift`/`roll` give
  neighbours, `u[k]` reads one place.
- Scheduling, the real work: a field stepped once a frame (`every`) must
  not cost w·h operations in one sample. The compiler computes `next[k]`
  at the sample that asks for place k, which is today's cost exactly:
  it's Halide's split between what is computed and when. That holds
  while shifts are of *stored* fields (`lap($u)`); a shift of a computed
  field (`lap(next)`) recomputes the neighbours, five times the work per
  layer. The first version could refuse it, with a message saying to
  store the field first, which is what the physics schemes do anyway.
- A field of filters (`dho` on a field, state at every place) is a
  separate, later question; at first it is an error saying so.

## Recommendation

**V, with `{x, y}` pairs**, built in this order: the pair syntax alone
(corpus bit-identical), then fields as values (pure operations,
`shift`/`roll`, coordinates, `u[k]`, per-place scheduling), then ridge,
phased_array, phasor_ring and mandelbrot converted, each bit-identical.
`each` and indexed stores stay for arrays that aren't fields (a scale
being rewritten, a history), and A's pair elements stay underneath.

Why V over B, now that braces take away the clash between pairs and
fields: it reads like the physics in all three demos, not just the ring.
It keeps the time levels explicit where observation needs them. It
handles fields that feed each other inside a step, which is how Maxwell
is computed. And ∇², curl and the rest become defs anyone can write, not
features of one construct. B's one advantage is that nothing migrates.

The decision that is yours: whether aither's pairs change to `{a, b}`.
Everything else follows from it.
