# Fields of phasors: which way is aither's

**Status (2026-10-29, latest): direction chosen, not built. M, a field
as its modes,** for media described by their spectrum, and X, coordinates
like `t`, for fields that need places (contacts, terrain). Both are at
the end, after "The limitation", which they answer. Step 1 of M needs no
language change. A (pair
elements in state arrays) is built and is how fields are written until
something better is found. The candidates considered so far, measured
against aither's aim to be the best language for field physics:

- **B, a field and its local law:** `field(shape, init, law)`, the law
  saying how one place's next value follows from it and its neighbours.
  Pairs stay `[a, b]`.
- **V, the field as a value:** a field is a value like a number;
  arithmetic is at every place at once; neighbours are whole shifted
  fields, so ∇² is a def on fields. It needs pairs written `{a, b}`,
  because `[ … ]` has to mean only "a field".

Nothing is built for either yet. The corpus decides nothing here; both
must render the converted demos bit-identical to today.

The test, from MANIFESTO.md: signals as field values, state as field
configuration, **evolution as a local update rule**, observation as
projection, coupling as shared field access. And PHILOSOPHY.md's: every
primitive earns its place against what the existing ones already say.

## The ladder: most fields need no new feature

What physics already reads well, because the kind of field decides it:

| the field | what writes it in aither today | needs state per place? |
|---|---|---|
| a linear medium driven at its modes (a plate, a drum, a room's resonances) | a sum of its modes: `sum(N, n => dho(drive * shape(n, x), f(n), d))` (demos/chladni) | no |
| a linear medium carrying waves (a string, a tube, a room's echoes) | travelling waves as delays (d'Alembert: f(x - ct) + g(x + ct)), a waveguide | no, delays are the field |
| oscillators all coupled to all (Kuramoto's own model, a bridge, a soundboard) | one shared cell, the mean field (sympathy.aither's `$board`) | no: one cell |
| polyphase, rotating fields | turns of one phasor (three_phase.aither) | no |
| **a medium stepped by a local rule** (a membrane by leapfrog, Maxwell by FDTD, a ring of oscillators, a lattice, reaction-diffusion, any per-place iteration) | a stored field: one value per place | **yes** |

Only the last row is in question. B and V are two ways to write it.

## The three demos

Today's forms are the files: `demos/ridge.aither` (a 64×36 membrane by
leapfrog, terrain, a soaking border, a mast), `patches/phasor_ring.aither`
(twelve phasors in a ring, nonlinear), `patches/mandelbrot.aither` (state
at every place, no neighbours, two fields where one feeds the other).
Both forms are written from those, line for line where the physics is the
same; the comments are cut.

### ridge, today (A)

```
let k = pixel_index(w, h)
let x = k mod w
let y = int(k / w)
...
$u = array(w * h, every = w * h)
$v = array(w * h, every = w * h)
let c  = $u[k]
let p  = $v[k]
let lt = if x > 0 then $u[k - 1] else 0
let rt = if x < w - 1 then $u[k + 1] else 0
let up = $u[k - w]
let dn = $u[k + w]
let lap = lt + rt + up + dn - 4 * c
let edge = min(min(x, w - 1 - x), y)
let soak = if edge < 4 then 0.8 + 0.05 * edge else 1
let drive = if k == mast then sin($phase) else 0
let next = if earth then 0 else (2 * c - p + 0.25 * lap) * soak + 0.5 * drive
$u[k] = next
$v[k] = c
let z = [next, (next - c) / omega]
```

The sample computes one place; the program is written from inside that
place. The left and right edges are guarded by hand, because a flat index
wraps across rows.

### ridge in B

```
def lap(at, u): at(-1, 0) + at(1, 0) + at(0, -1) + at(0, 1) - 4 * u
def ground(x): h - 3 - max(0, 14 * (1 - abs(x - 36) / 11.5))
def soak(x, y):
  let edge = min(min(x, w - 1 - x), y)
  if edge < 4 then 0.8 + 0.05 * edge else 1

$u = field([w, h], 0, every = w * h, (u, was, at, place) =>
  let [x, y] = place
  let drive = if x == 5 and y == h - 9 then sin($phase) else 0
  if y >= ground(x) then 0 else (2 * u - was + 0.25 * lap(at, u)) * soak(x, y) + 0.5 * drive)

let next = $u[k]
let z = [next, (next - $u.was[k]) / omega]      # needs a way to read the step before
```

- Good: the leapfrog line is the physics; `at(dx, dy)` is 2-D, so the
  edge guards are gone (past the edge reads 0, the declared edge).
- Awkward: `was` is inside the law, but the picture needs it too
  (the phasor is the field and its rate), so B needs a second way in,
  `$u.was[k]` or such. Everything place-dependent (terrain, soak, the
  mast) becomes a def of `place`, threaded through the law's arguments.
  The law takes four arguments, most laws use two.

### ridge in V

```
let x = across(w, h)                 # a field: every place's column
let y = down(w, h)                   # ... and its row
def lap(u): shift(u, -1, 0) + shift(u, 1, 0) + shift(u, 0, -1) + shift(u, 0, 1) - 4 * u

let earth = y >= h - 3 - max(0, 14 * (1 - abs(x - 36) / 11.5))
let edge = min(min(x, w - 1 - x), y)
let soak = if edge < 4 then 0.8 + 0.05 * edge else 1
let drive = if x == 5 and y == h - 9 then sin($phase) else 0

$u = field([w, h], 0, every = w * h)    # the field now
$v = field([w, h], 0, every = w * h)    # a frame ago
let next = if earth then 0 else (2 * $u - $v + 0.25 * lap($u)) * soak + 0.5 * drive
$v = $u
$u = next

let z = {next[k], (next[k] - $v[k]) / omega}   # the sample: the field seen at this place
```

- Good: it reads like the textbook: u_next = 2u - u_prev + c²∇²u. `lap`
  is ∇², a reusable value. The terrain and the border are fields, written
  as plainly as the numbers were. The two time levels are explicit
  (`$v = $u`), so observation reads either. The sample is a projection,
  `next[k]`: the manifesto's "observation as projection", literally.
- Awkward: `x` is now a field, not this sample's column; a patch that
  wants both says `across(w, h)` and `k mod w`. `if` on a field picks at
  every place. `shift` past the edge reads 0; a soaked or wrapped edge
  is `shift(…, edge = …)`.

### phasor_ring, today (A)

```
$z = array(n, [1, 0])
each(n, i => $z[i] = law($z[i], $z[(i + n - 1) mod n], $z[(i + 1) mod n], step(i, spread), couple))
```

### phasor_ring in B

```
$z = field(n, [1, 0], edge = ring, (z, was, at, i) =>
  let moved = turn(z, step(i, spread)) + (at(-1) + at(1) - z * 2) * couple
  moved / amplitude(moved))
```

### phasor_ring in V

```
let steps = field(n, i => step(i, spread))      # each place's own turn
$z = field(n, {1, 0})
let moved = turn($z, steps) + (roll($z, -1) + roll($z, 1) - $z * 2) * couple
$z = moved / amplitude(moved)
```

Both lose the index arithmetic. V reads as the equation of motion of the
whole ring; B reads as the equation at one oscillator. `roll` wraps
(NumPy's name); `shift` doesn't.

### mandelbrot, today (A)

```
$z = array(w * h, [0, 0])
$m = array(w * h, [0, 0])
let z = $z[k]
let next = if amplitude(z) > 2 then z else turn(z, z) + c
$z[k] = next
let seen = $m[k] + (next - $m[k]) * 0.05
$m[k] = seen
```

### mandelbrot in B

```
$z = field([w, h], [0, 0], every = w * h, (z, was, at, place) =>
  if amplitude(z) > 2 then z else turn(z, z) + point(place))
$m = field([w, h], [0, 0], every = w * h, (m, was, at, place) =>
  m + ($z[place] - m) * 0.05)
```

- Awkward, and it changes the picture: each law reads every field as it
  was, so `$m` follows `$z` a frame late. Two fields where one feeds the
  other inside a step is the shape of Maxwell's equations by FDTD (Yee:
  E from H, then H from the new E), the scheme field physics is computed
  with. B would need an order between laws, which is the thing B was
  meant to avoid.

### mandelbrot in V

```
let c = place_point(w, h) * 1.5 - {0.5, 0}     # every place's point, a field
$z = field([w, h], {0, 0}, every = w * h)
$m = field([w, h], {0, 0}, every = w * h)
let next = if amplitude($z) > 2 then $z else turn($z, $z) + c
let seen = $m + (next - $m) * 0.05
$z = next
$m = seen
seen[k] / (1 + amplitude(seen[k]))
```

The order is the `let`s, as everywhere else in aither. Yee's scheme is
the same shape: `let e = $e + curl($h) * k`, `$h = $h - curl(e) * k`,
`$e = e`.

## What each costs

**B**
- One construct, `field(shape, init, law)`, with `at`, `was`, `place`,
  edges and `every`. Pairs are untouched, nothing migrates.
- It says what `each` with held-back stores already says, more
  specifically (the status this note first had rejected B for that).
- Fails on fields that feed each other inside a step (mandelbrot's two,
  Maxwell's E and H) without an order between laws.

**V**
- Pairs become `{a, b}`: about 245 two-element literals and 57
  `let [a, b] =` destructurings across 95 `.aither` files, plus about 90
  in SPEC, COMPOSING, PHASORS and the stdlib. Mechanical, one commit of
  its own, and the corpus proves it changed no sound. `[a, b]` stops
  meaning a table of two in one place and a pair in another (SPEC,
  "Arrays"): brackets are tables and fields, braces are pairs.
- A field type in the compiler: a shape, and every pure operation and
  pure builtin applied at every place. `field(n, i => …)` tabulates,
  `across`/`down`/`place_point` give coordinates, `shift`/`roll` give
  neighbours, `u[k]` reads one place.
- Scheduling, the real work: a field stepped once a frame (`every`) must
  not cost w·h operations in one sample. The compiler computes `next[k]`
  at the sample that asks for place k, which is today's cost exactly:
  it's Halide's split between what is computed and when. That holds
  while shifts are of *stored* fields (`lap($u)`); a shift of a computed
  field (`lap(next)`) recomputes the neighbours, five times the work per
  layer. The first version could refuse it, with a message saying to
  store the field first, which is what the physics schemes do anyway.
- A field of filters (`dho` on a field, state at every place) is a
  separate, later question; at first it is an error saying so.

## Recommendation (superseded: see "The limitation")

**V, with `{x, y}` pairs**, built in this order: the pair syntax alone
(corpus bit-identical), then fields as values (pure operations,
`shift`/`roll`, coordinates, `u[k]`, per-place scheduling), then ridge,
phased_array, phasor_ring and mandelbrot converted, each bit-identical.
`each` and indexed stores stay for arrays that aren't fields (a scale
being rewritten, a history), and A's pair elements stay underneath.

Why V over B, now that braces take away the clash between pairs and
fields: it reads like the physics in all three demos, not just the ring.
It keeps the time levels explicit where observation needs them. It
handles fields that feed each other inside a step, which is how Maxwell
is computed. And ∇², curl and the rest become defs anyone can write, not
features of one construct. B's one advantage is that nothing migrates.

The decision that is yours: whether aither's pairs change to `{a, b}`.
Everything else follows from it.

## Also considered after V

- **V was turned down (by the author) for simplicity.** It gives aither a
  second way of thinking: a program would be one place at one moment in
  some lines and a whole field in others. `x` would be a column or a
  field of columns, every operator and builtin would get a second meaning,
  and every patch would change to `{a, b}` pairs to serve one row of
  the ladder.
- **Shaped arrays with a declared edge** (`array([w, h])`,
  `edge = ring`, `$u[x - 1, y]` reads 0 past the edge). It removes the
  subscript arithmetic and the edge guards, and adds no concept. But the
  field is still a data structure indexed by hand, so it tidies the
  limitation without lifting it.
- **S, space written like time.** `$x` is x a moment ago; `$u(-1, 0)`
  would be u one place over, a moment ago, in a `space(shape, …)` body
  written for one place. Its strengths: one way of thinking (one place,
  one moment), the light cone as the language's rule, and a field of
  filters for free. Turned down for now. It is still a new construct,
  and Yee's scheme (H from the *new* E next door) needs a present read
  it forbids.

## The limitation

aither's model is one sample at one place: a program is what happens
here, now, and `$` reaches one moment back. That is why it is simple, and
why waves, modes, coupling through a shared cell and polyphase all read
well (the ladder). A field is many places at one moment, and aither has
no way to name "all the places" as one thing. So a field's law can only
be written from inside one place, reaching the others by index (A), or
by a construct that is a second language inside the first (B, V, S).
Every fix so far has cost the simplicity it was meant to serve.

## What Julia does, and what aither would need

Julia is the nearest language to "the best for field physics", and it
gets there with a few general ideas rather than a field feature:

- **Arrays are values, and broadcasting is marked.** `u .+ v`, `f.(u)`,
  `@. 2u - v + c * lap`: the dot says "at every element", so a scalar
  operator never silently means something else, and the dotted
  expression is fused into one loop with no temporaries. This answers the
  objection to V: fields as values *without* every operator gaining a
  second meaning, because the reader sees the dot.
- **One definition, many types (multiple dispatch, specialised when
  compiled).** `lap(u)` is written once and works on a 1-D, 2-D or GPU
  array, on dual numbers for derivatives, on complex. A pair would be a
  small static vector (StaticArrays' `SVector{2}`), one type among
  others, not the shape of every value.
- **The law is separated from the integrator.** DifferentialEquations.jl
  takes `du = f(u, p, t)`, the right-hand side, and the solver (leapfrog,
  RK4, symplectic, adaptive) is a choice made apart from it.
  ModelingToolkit goes further: equations written symbolically, code
  generated from them. In aither the integrator is written into the law
  by hand (ridge's `2 * c - p + …`) or baked into a builtin (`dho`).
- **Stencils as library macros, not language.** ParallelStencil.jl and
  similar write a stencil once and generate the CPU or GPU loop; the
  language only has to make such libraries possible (macros, staged
  compilation).

So what would have to happen to aither, roughly in order of size:

1. **A value that is many values,** with an explicit mark for "at every
   place" (Julia's dot, or one like it), so the one-place reading of
   every existing line stays true. This is the least that lifts the
   limitation.
2. **Defs that work on any shape** (a field of numbers, of pairs, 1-D or
   2-D), specialised by the compiler, so `lap`, `curl` and `div` are
   written once by anyone.
3. **The law apart from the stepping:** say `u'' = c² ∇²u`, choose how it
   is stepped. aither's own idea, f(state) → sample, would become
   f(state) → rate, with the integrator chosen by name. `dho` would be the
   first case of it, not a special one.
4. **Scheduling the compiler owns** (Halide's split of what from when):
   a field stepped once a frame costs one place per sample, as now.
5. Macros or staging, only if 1–4 leave libraries unable to say what
   they need.

Items 1 and 3 are the real questions, and 3 reaches past fields (every
filter and oscillator in the stdlib is a hand-written integrator). They
stay open here until one of them can be had without giving up "a program
is one sample at one place".

## M: a field is its modes

Field theory mostly works in modes, not places: the field is a sum of
waves, φ = Σ a_k · e^{i(k·x − ωt)}, each mode one phasor, its magnitude
how much of it there is, its phase where it is in its cycle. That is
aither's own idea, taken all the way: chladni's sum of modes and `dho`'s
exact rotation are already it, for linear fields.

### The proposed syntax (a gong)

```
let f0 = 70
$a = modes(12,
  spin = k => f0 * k * (1 + 0.06 * k),        # the dispersion: the free field, exact
  life = k => 7 / (1 + 0.35 * k),             # how long each mode rings
  energy = a =>                               # the interaction, written once
    6 * sum(p + q == r: a[p] * a[q] * conj(a[r]))
    + 0.5 * sum(k: amplitude(a[k]) ^ 4))
$a = $a + kick(k => exp(-k / 3)) * hit        # a felt mallet at the rim's angle 0
[at($a, 0.5), at($a, 2.1)]                    # heard at two points on the rim, now
```

| piece | what it says | the physics |
|---|---|---|
| `modes(n, spin, life, energy)` | a field held as its modes | the plane-wave expansion |
| `spin = k => …` | each mode's frequency | the dispersion relation ω(k), one line per medium |
| `energy = a => …` | the interaction energy; the motion of every mode is derived from it | the Hamiltonian |
| `sum(p + q == r: …)` | a sum over the modes a rule allows | a selection rule: momentum conserved round the rim |
| `amplitude(a[k]) ^ 4` | a mode's own size stiffens it | self-interaction (φ⁴): a hard hit's pitch sinks as it dies |
| `kick(k => …)` | a push spread over the modes | a point force, resolved into modes |
| `at($a, θ)` | the field observed at a place and the present moment | observation as projection |

Other media are the same shape: `spin = k => c * k` (a string, an air
column), `spin = k => sqrt(m * m + c * c * k * k)` (Klein–Gordon: waves
with mass, ringing on after the pluck), `spin = k => b * k * k` (a stiff
bar; Schrödinger).

Why `energy` rather than each mode's feed: written once, both directions
of every coupling follow from it and energy is conserved by
construction. Written by hand (two modes feeding a third, the third
feeding both back), the terms must be matched, and that is where
mistakes hide.

### Dimension lives in three places, not in coordinates

1. Which spins exist (the dispersion).
2. Which modes can talk (the selection rules: momentum is one number on
   a ring, three in a room, the same rule).
3. Where you listen (`at` turns each mode by k·x, a dot product in any
   dimension).

Everything else is a phasor with a magnitude and a spin. The dimension
can even be heard in the spectrum alone: the number of modes below a
frequency grows as that frequency to the power of the dimension (Weyl's
law), so a string's modes are evenly spaced, a plate's get denser in
proportion to frequency, a room's as its square. Spaces with no axes at
all (curved, a network of parts) are their spectra.

The limit: a spectrum does not fix a shape (Kac, 1966, "Can one hear the
shape of a drum?"; Gordon, Webb and Wolpert, 1992, two drums with the
same spectrum). The shape lives in the mode shapes `at` uses and in the
selection rules, which the syntax keeps.

Two ways to give a field its modes:

```
$room = modes(n, spin = k => 343 / 2 * length([k[0] / 5, k[1] / 4, k[2] / 3]))   # from geometry: a 5 × 4 × 3 m room
$hall = modes(n, spin = measured.freq, life = measured.life)                      # from a recording, no geometry
```

The second is new for music: record a stairwell, a tank, a bowl, take
its modes from the recording, and play the space: strike it, couple it to
a gong, drive it nonlinearly. A grid can't, since it needs the geometry.

### Time: oscillation leaves the field, change stays

A free mode's amplitude never changes; all its motion is the spin, ω·t.
So the field is held in the frame that turns with each mode (the
interaction picture): the stored amplitudes stand still, and time enters
as space does, as one turn where and when you observe, k·x − ω·t. Under
ω² = c²k² + m² the two are symmetric; `at` observes at an event, a place
and a moment.

What still happens in time is change: a strike, damping, modes trading
energy. That is cause and effect, and stays. The fast motion becomes
geometry (the spin); only what happens to the field is evolution.

- Pitch is exact: each mode's phase is ω·t from the one clock, not
  summed sample by sample, as aither's turning path for steady sines.
- In the turning frame a coupling a_p · a_q · conj(a_r) turns at
  ω_p + ω_q − ω_r: near zero it is resonant and moves energy, fast it
  averages away. Which modes talk falls out of the frequencies.
- Not a control rate: the amplitudes change slowly but are computed
  every sample. The gain is exactness and clarity, not speed.
- The output stays in time: a speaker needs a sample at each moment. `t`
  is the moment observed, as θ is the place.

### What is new to the language

Almost nothing:

| piece | in today's aither |
|---|---|
| `modes(n, spin, life)` | a pair state array and `each`, every mode turned by `rotate([exp(-dt / life), 0], TAU * spin * dt)` |
| `at($a, θ)` | `sum(n, k => turn($a[k - 1], rotate([1, 0], k * θ)))` |
| `kick(k => …)` | an add inside the same `each` |
| `sum(p + q == r: …)` | `sum(n, p => turn($a[p - 1], $a[r - p - 1]))`: reads past the ends give `[0, 0]`, so the rule falls out of the indices |
| self-interaction | the spin sped up by `amplitude($a[i])` |
| modes from a recording | a tool: an offline analysis writes the frequencies and lifetimes as tables, imported like `lib/notes.aither` |

Whether `modes` can be one stdlib def needs checking (it owns a state
array whose size is an argument; defs keep per-call state, as `lockin`
in demos/plate does, and lambdas passed to defs are inlined).

The one new thing is deriving the motion from `energy`: each mode's
push is the derivative of the energy with respect to that mode's
conjugate (the Wirtinger derivative), worked out by the compiler. It is
contained (`energy` is pure: no state, no time), but it is real compiler
work. Sugar, not needs: the rule form of `sum`, and mode labels of three
numbers (a pair covers two; three need tables of labels).

Order:
1. `modes`, `at` and `kick` as stdlib defs, couplings written by hand;
   no language change. patches/gong.aither (a draft, unverified) is this
   by hand.
2. If hand-written couplings prove error-prone on real patches, that is
   the evidence `energy` earns its place.
3. The mode-measuring tool, when a real space is to be played.

Where M is weak: a nonlinearity cheap at one place (a fret, a beater's
contact, clipping where the field is strong) couples every mode to every
other in mode space, N² or worse. Those are X's.

## X: coordinates, like `t`

For fields that need places: `x` and `y` given to the program as `t`
is, a declared domain (size, resolution in metres, edges), state read at
another place (`$u(x - dx, y)`, or spatial derivatives as operators), and
an observation for the sample. Not state, so not `$x`. It is S without
the construct; its details are open. Users choose M or X by the medium.
